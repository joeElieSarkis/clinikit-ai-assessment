01

Start with the data.

Each row represents an appointment. The target is no_show: 1 means the patient did not attend; 0 means they attended.

Appointment ID is excluded from prediction. Gender is reserved for the subgroup audit. No patient identifier or calendar date is available, so patient-level and temporal validation remain untested.

Three separate partitions

Identical predictor profiles stay together. The model is selected inside training folds; the outreach threshold is set on validation data. The test set measures the frozen choice.

The prediction assumes reminder status is already known before the visit. The data contains no timestamps to verify that assumption.

02

A baseline comes first.

A model predicting attendance for everyone looks accurate on this imbalanced dataset. Average precision tests whether actual no-shows tend to receive higher scores. Selection uses five-fold grouped cross-validation on training data.

Candidate Average precision ROC AUC Brier score ↓

AP is shown as the fold mean ± standard deviation. It is average precision, not trapezoidal PR area. Higher AP and AUC are better; lower Brier score is better. The selected model receives sigmoid calibration from training-only out-of-fold predictions.

06

From a score to a workflow.

  1. Validate the snapshot

    Confirm that every predictor is available at scoring time and the historical counts exclude the current appointment.

  2. Score in shadow mode

    A scheduled backend job loads the versioned model and records probability, threshold, model version, and time. Staff decisions continue unchanged.

  3. Review an outreach queue

    After prospective validation, reception staff review suggested follow-ups within an agreed daily capacity. Scores do not restrict access to care.

  4. Measure the actual outcome

    Monitor calibration, missed visits, contact workload, subgroup performance, and data drift. A controlled rollout is needed to measure the effect of outreach.

Limits of this assessment

  • The source has no patient ID, appointment date, event timestamps, or external validation cohort.
  • Reminder status is an observed feature. Its model importance is not an estimate of a reminder's causal effect.
  • Imputers and encoders support missing values and unseen categories, but these conditions need monitoring in a real feed.
  • The model and threshold were selected before test evaluation. The saved model was not refitted on validation or test rows.
  • This report contains aggregate results and synthetic examples. It makes no model API calls and performs no patient outreach.
